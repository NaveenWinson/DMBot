# DMBot: notes for Claude

DMBot automates replies to comments on the owner's own Instagram account, **@twoticket_tribe**. When someone comments a
keyword on a reel, it does three things:
1. posts a public reply;
2. sends a **follow-gate DM**;
3. sends the **real DM** after Instagram confirms the person follows the account.

It runs on **Zoho Catalyst**: two Advanced I/O functions, the Data Store, and a React admin page.
The full setup, the Data Store schema and troubleshooting are in [docs/setup.md](docs/setup.md). Read it before changing infrastructure.

## Layout
```
shared/           all logic (CommonJS), with tests in shared/test (node:test)
  webhook-handler.js  comment webhook → match → claim row → first DM + public reply
  unlock.js           follow-gate: messages webhook → find waiting row → follow check → real DM
  instagram.js        Graph API client (graph.instagram.com, API_VERSION v26.0); IG_MOCK=1 gives a fake client
  store.js            Data Store via ZCQL; ids/usernames are validated before they go into SQL
  match.js            normalize() + exact keyword match;  replies.js: the 12 rotating public replies
  signature.js        X-Hub-Signature-256 check;  rules-admin.js: rule validation;  guards.js;  reels.js
functions/webhook/  Express: GET = Meta verify handshake, POST = comments + messages (keeps the raw body for the signature)
functions/admin/    Express: Catalyst sign-in + ADMIN_EMAIL guard; /cron/* routes are protected by the x-cron-secret header
functions/*/lib/    GENERATED by `npm run sync-shared` (git-ignored). Edit shared/, never lib/.
client/             Vite + React 18 + HashRouter, CSS Modules, served at /app/
  pages: Reels, ReelRules (/reels/:id), Keywords, Activity, Settings, Privacy (public, needed for Meta Live mode)
scripts/            deploy-env.js (injects .env.deploy), sync-shared.js (MAP of shared files per function), setup-datastore.js
```

## Commands
- **Tests:** `npm test` (backend) and `cd client && npx vitest run` (client). Both must pass; deploy.sh runs them.
- **Deploy:** `./deploy.sh`, from DMBot/. It runs the tests, then sync-shared, then the client build, then injects the secrets, then runs `catalyst deploy`, then restores the files.
  - `DEPLOY_DRY_RUN=1 ./deploy.sh` rehearses everything without deploying.
  - The CLI is at `~/.npm-global/bin/catalyst`, which **isn't on the login-shell PATH**. deploy.sh finds it anyway.
  - A deploy takes about 1–2 minutes. Run it in the background. If `catalyst deploy` seems stuck, kill `deploy.sh`; its trap restores the files.
- **Secrets:** `.env.deploy` (git-ignored, chmod 600) holds:
  - `META_APP_SECRET` (the **Instagram app secret**) and `WEBHOOK_VERIFY_TOKEN`, for the webhook function;
  - `ADMIN_EMAIL` and `CRON_SECRET`, for the admin function.

  The template is `.env.deploy.example`. Never print these values or commit them. Read them in a shell
  (`grep '^CRON_SECRET=' .env.deploy | cut -d= -f2-`) without echoing them.

## Behaviour (decided with the owner)
- **Keyword rules:**
  - Rules are **per reel only**.
  - The match is **exact**: the whole comment, ignoring case, extra spaces and Unicode width (NFKC).
  - Only top-level comments count, and the account's own comments are ignored.
- **Public reply:** always one of the 12 in `shared/replies.js`, picked at random, **never the same twice in a row**. The previous reply is read from `Processed.reply_text`. Rules have no reply field.
- **Follow-gate (applies to every keyword):**
  - The first private reply is the rule's `gate_text`, sent with an "I followed ✅" quick reply (`UNLOCK:<ruleId>`). If the gate text doesn't mention DONE, a how-to line is added.
  - The confirm word is always **DONE**, for every keyword. Typing DONE unlocks every keyword the person is waiting on; the button unlocks only its own.
  - The follow check is `GET /<igsid>?fields=is_user_follow_business`. It only works after the person has messaged, which is why their reply is the trigger.
  - Unlocking is allowed for 7 days (`unlock_expires_at`), and only waiting rows are ever answered, so ordinary DMs get no reply.
  - Rules without `gate_text` (older ones) send the real DM straight away.
- **Duplicates:** Meta retries webhooks. The **unique** column `Processed.comment_id` is the "already handled" marker. Rows that have already been unlocked stop matching, so the real DM is never sent twice.

## Instagram/Meta facts learned the hard way
- Webhooks are signed with the **Instagram app secret**, not the main App secret. Using the wrong one gives `bad signature` and every real webhook gets a 401.
- In Development mode, `/comments` returns `data: []` (with paging cursors) even when `comments_count` is higher. Publishing the app fixed it. App Review and tester roles for commenters were **not** needed for the owner's own account.
- There is **no follower/follow webhook**. Only one private reply is allowed per comment, within 7 days. After the person replies, normal messages are allowed for 24 hours.
- Comment `from.id` and messaging `sender.id` *may* differ. unlock.js falls back to matching by username (fetched from the profile once the person has messaged).
- Old comments are never re-sent as webhooks. Rate limit: about 200 calls per hour for the app (each matching comment uses about 2).
- Catalyst passes the raw request body through, so the signature check works. `updateRow` may ignore nulls, so use '' instead.
- **Data Store changes:** a new column must be added in the console **before** deploying code that writes it. Ask the owner to add it, then deploy.
